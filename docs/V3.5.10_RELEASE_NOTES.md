# CodePilot V3.5.10 Release Notes

**Release Date:** 2026-06-16
**Status:** Stable release with separate mode as default. Grouped mode remains experimental only.

---

## Release Status

V3.5.10 is a stabilization release. The default agent orchestration mode (`separate`) is unchanged from V3.5.9. An experimental `grouped` mode was added behind a feature flag but failed its first real benchmark and is **not production-ready**.

---

## Main Changes

* Added `REVIEW_AGENT_MODE=separate|grouped` environment variable
* `separate` remains the recommended and default mode (4 independent LLM calls, V3.5.9 behavior)
* `grouped` mode added behind feature flag (2 grouped LLM calls, 4 logical agent outputs)
* Grouped mode preserves 4 logical Agent identities in output
* Grouped mode benchmarked against real MiMo — found not production-ready
* Parser defensive robustness improved for unexpected LLM JSON structures
* Chinese report benchmark warning verified as false positive (data correct, label cosmetic)
* Project docs updated to mark grouped as experimental
* Harness docs updated to reflect V3.5.10 status

---

### Grouped Mode (Experimental)

| Metric | Value |

### Verdict

Grouped mode is **3x slower** and produced **0 findings**. The grouped prompt is too large for current timeout settings, and the schema is less stable with MiMo. `separate` remains the recommended default.

---

## User-Facing Recommendation

For demos, production-like usage, and real reviews:

```
REVIEW_AGENT_MODE=separate
```

Do not use `grouped` mode unless explicitly testing experimental orchestration. It is not faster, not more reliable, and not production-ready.

---

## Known Limitations

* Grouped mode prompt is too large for 180s read timeout
* Grouped schema is less stable with MiMo
* Grouped mode can timeout or produce parse errors
* Runtime still depends on provider latency
* Chinese report quality remains deterministic but can continue improving
* MaintainabilityAgent had 1 parse error in separate mode (non-blocking)

---

## Recommended Next Version

V3.5.11 or V3.6 should focus on one of:

* Evidence explanation quality improvements
* Frontend report UX enhancements
* Smaller prompt strategy for separate mode
* Robust benchmark tooling
* Only revisit grouped mode as a separate research task with a fundamentally different prompt strategy
