# V3.7 Step 3 — MiMo Chinese Report Fallback

> Status: Complete
> Date: 2026-06-17

## Problem

Mock zh reports use deterministic templates from `zh_presentation.py`, so they pass
the English leakage gate. MiMo generates novel English prose that existing phrase
tables don't cover:

### MiMo English sentences in zh sections

- "The test cases for find_best_app show..."
- "Consider simplifying the discovery logic..."
- "May lead to user confusion..."
- "Future changes to static file serving logic..."
- "Need to ensure backward compatibility..."
- "This is an established pattern..."
- "The current implementation may handle edge cases..."

### Indexer metadata leaking into zh reports

The indexer (`backend/services/indexer.py`) generates English metadata strings:

- "Python repository with 83 Python files; analyzed 83 and skipped 0"
- "104 resolved internal relationships"
- "hubs: src/flask/globals.py, ..."
- "20 modules participate in cycles"
- "Entry points:", "Core modules:", "Dependency structure:"

### Broken evidence references

- `[[E?]]` double-bracket patterns (MiMo artifact)
- `[[E1]]`, `[[E2]]` instead of `[E1]`, `[E2]`

## Why Deterministic Fallback Is Safer Than Auto-Translation

1. **Deterministic**: Same input always produces same output. No LLM variance.
2. **No hallucination**: Templates are hand-written Chinese, verified in tests.
3. **No new facts**: Templates say "相关证据显示..." without inventing specifics.
4. **Auditable**: Every template is in `zh_presentation.py` with a test.
5. **Fast**: No LLM call, no latency, no cost.

Auto-translation would add LLM latency, cost, and risk of generating incorrect
Chinese that sounds plausible but misrepresents the finding.

## Architecture

All Chinese fallback logic stays centralized in:
`backend/reviewers/zh_presentation.py`

Other backend files only call `zh_presentation` functions. No phrase tables
in renderers, API handlers, or models.

### Pipeline flow

```
1. repair_zh_findings()        — fix English display.zh fields pre-render
2. render_localized_report()   — translate headings, labels, prose, evidence IDs
3. finalize_zh_report()        — repair metadata + normalize + clean [[E?]]
```

## Changes Made

### 1. Category-specific description templates

Added `_DESCRIPTION_TEMPLATES` dict with MiMo-safe descriptions per category:

| Category | Template |
|----------|----------|
| architecture | "相关证据显示该区域涉及模块发现、入口识别或公共边界，变更前需要确认现有行为。" |
| code_smell | "相关证据显示该区域存在重复逻辑、复杂职责或维护风险。" |
| maintainability | "相关证据显示该区域后续维护成本较高，建议优先补充测试和边界说明。" |
| refactor | "相关证据显示该区域存在可简化的结构或路径处理逻辑，适合在测试保护下小步重构。" |
| (unknown) | "该问题需要关注和审查。" (generic fallback) |

### 2. Indexer metadata repairs

Added `_INDEXER_METADATA_REPAIRS` list with regex replacements:

| English Pattern | Chinese Replacement |
|----------------|---------------------|
| `resolved internal relationships` | `已解析内部依赖关系` |
| `modules participate in cycles` | `个模块参与循环依赖` |
| `hubs:` | `依赖枢纽：` |
| `Entry points:` | `入口文件：` |
| `Core modules:` | `核心模块：` |
| `Supporting modules:` | `支撑模块：` |
| `Dependency structure:` | `依赖结构：` |
| `analyzed X and skipped Y` | `已分析 X 个，已跳过 Y 个` |
| `Python repository with N Python files` | `Python 仓库，包含 N 个 Python 源文件` |

### 3. Evidence reference cleanup

- `[[E?]]` → `[E?]` (double-bracket normalization)
- `[[E1]]` → `[E1]` (numbered double-bracket normalization)
- Valid `[E1]`, `[E2]` preserved

### 4. MiMo English sentence starters

Added 45+ English sentence starter patterns to the final gate
(`assert_no_english_natural_language_zh`):

- "The test cases", "Consider simplifying", "May lead to"
- "Future changes to", "Need to ensure", "This is an established"
- "The current implementation", "The selected evidence"
- "Note that", "Please note", "It is important"
- "You should", "We recommend", "One approach"
- ... and more

### 5. Strengthened final gate

`assert_no_english_natural_language_zh()` now checks:
- 3+ consecutive common English words (existing)
- 45+ MiMo sentence starters (new)
