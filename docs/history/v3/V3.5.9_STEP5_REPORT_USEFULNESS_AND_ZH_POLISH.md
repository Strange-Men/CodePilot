# V3.5.9 Step 5 — Report Usefulness and Native Chinese Quality

> Status: Complete
> Date: 2026-06-16

## 1. Baseline Issues

The Chinese report had several quality gaps:

- **English template residue**: Labels like `Recommendation:`, `Impact:`, `First step:`, `Validation tests:`, `Category:`, `Grounding:` leaked into zh reports through `to_localized_markdown()`.
- **Translation-style Chinese**: Labels like "第一步建议" felt translated rather than native. "Category" was translated as "类型" instead of "问题类型".
- **No priority guidance**: Users couldn't quickly tell which findings to fix first.
- **No evidence explanation**: Evidence IDs were listed but not explained.
- **Generic empty-agent wording**: Raw "completed/validated" status text appeared instead of natural Chinese.
- **DEFAULT_SECTION_CONTENT never translated**: "No critical findings detected..." stayed English in zh reports.

## 2. Priority Decision Layer

New module: `backend/reviewers/priority_layer.py`

Deterministic P1/P2/P3 assignment based on:
- Severity weight (critical=4, high=3, medium=2, low=1, informational=0)
- Confidence score
- Number of affected files
- Category weight (architecture=2, code_smell=1, maintainability=1, refactor=0)

**Thresholds:**
- P1: severity ≥ high AND confidence ≥ 0.7
- P2: severity ≥ medium
- P3: everything else

**Output format:**
```markdown
# 优先处理建议

## P1：建议优先处理
* **问题标题**
  * 为什么重要：...
  * 建议先做：...
  * 涉及文件：...
  * 证据引用：...
```

If no P1: "本次未发现需要立即处理的 P1 问题。"

Injected after 执行摘要 (Executive Summary) in zh reports only.

## 3. Chinese Wording Changes

### Labels (localization.py)

| English | Old Chinese | New Chinese |
|---------|------------|-------------|
| First step | 第一步建议 | 建议先做 |
| Category | 类型 | 问题类型 |
| Where | 位置 | 涉及文件 |
| Evidence | 证据 | 证据引用 |
| Grounding | 证据定位 | 证据说明 |
| Likely responsibility area | 可能的责任区域 | 责任范围 |

### Empty Agent Wording

| English | Old Chinese | New Chinese |
|---------|------------|-------------|
| No validated findings. | 暂无已验证的问题发现。 | 暂未发现明确的问题。 |
| No validated finding was produced. | 未产出已验证的问题发现。 | 暂未产出需要单独列出的问题发现。 |

### DEFAULT_SECTION_CONTENT

| English | Chinese |
|---------|---------|
| No critical findings detected from the available repository summaries. | 暂未从可用的仓库摘要中检测到明确的问题。 |

### New Prose Replacements

- `Status: **completed**; validation: **validated**.` → `状态：**已完成**；验证：**已通过**。`
- `Not available` → `暂无数据`
- `none detected` → `未检测到`

## 4. Evidence Explanation Behavior

- `to_localized_markdown("zh")` now uses `证据说明：` label for grounding evidence
- Evidence IDs and source locations are preserved unchanged
- No hallucinated explanations — only existing metadata is used

## 5. Action Plan Changes

The action plan section (rendered by `report_composer.py`) is structural English that gets translated by the localization layer. New Chinese labels:

- **Why it matters:** → **为什么重要：**
- **Where:** → **涉及文件：**
- **First step:** → **建议先做：**
- **Evidence:** → **证据引用：**
- **Validation tests:** → **验证方式：**
- **Caveat:** → **注意事项：**
- **Change risk:** → **变更风险：**
- **Likely responsibility area:** → **责任范围：**

## 8. Remaining Limitations

- The priority layer is deterministic — it does not use LLM for reasoning about which findings are most important.
- Evidence explanations are limited to existing metadata; no source snippet analysis.
- The action plan structure is still generated in English by `report_composer.py` and translated post-hoc.
- `report_composer.py` still calls `finding.to_markdown()` (English) for contract sections; the zh labels only apply when `to_localized_markdown("zh")` is called.
