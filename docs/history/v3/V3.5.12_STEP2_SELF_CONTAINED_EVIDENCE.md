# V3.5.12 Step 2: Self-Contained Markdown Evidence Appendix

> Date: 2026-06-17
> Status: Implemented

## Problem

Exported Markdown reports exposed long internal evidence IDs such as `ev_d0b430fe6ccd2d0f552c`. These IDs are useful internally but ugly for users. On free Render deployments using `/tmp` SQLite, the exported Markdown is the only durable artifact — but it was hard to understand offline because evidence references were opaque and the appendix lacked code snippets.

## Product Decision

- **Raw ev_* IDs remain internal** — stored in DB, used in validation logic, never removed.
- **User-facing Markdown uses E1/E2/E3** — short, readable display refs in first-appearance order.
- **Exported Markdown is the durable artifact** — includes self-contained evidence appendix with code snippets for offline readability.
- **No paid storage required** — no Postgres, Supabase, Neon, or persistent Render disk.

## Evidence Display Model

### Mapping Rules

- `EvidenceDisplayMap` builds a deterministic mapping from raw ev_* IDs to E1/E2/E3.
- **First-appearance order** within a report is preferred.
- **Same raw ID always maps to the same E-number** in the same report.
- Raw ev_* IDs are **never shown** in user-facing Markdown sections.
- Unknown IDs pass through unchanged (backward compatibility).

### Display Format

In English:
```
Evidence: [E1] [E2]
```

In Chinese:
```
证据引用：[E1] [E2]
```

## Evidence Appendix Format

### English

```markdown
# Evidence Appendix

## E1 · src/flask/app.py:392-412

* Type：symbol
* Symbol：send_static_file
* Related findings：Duplicate send_static_file method
* Description：This evidence was derived from parsed code symbols or structured repository context.

```python
def send_static_file(self, filename):
    ...
```

## E2 · tests/test_app.py:100-140

* Type：symbol
* Symbol：test_basic_dispatch
* Related findings：Missing test coverage for error paths
* Description：This evidence was derived from parsed code symbols or structured repository context.

```python
def test_basic_dispatch(self):
    ...
```
```

### Chinese

```markdown
# 证据附录

## E1 · src/flask/app.py:392-412

* 类型：symbol
* 符号：send_static_file
* 关联问题：重复的 send_static_file 方法
* 说明：该证据来自已解析的代码符号或结构化仓库上下文。

```python
def send_static_file(self, filename):
    ...
```
```

### Limits

- Max 30 evidence appendix entries per report
- Each snippet: max 20 lines, max 1600 characters
- If more than 30 entries, remaining are omitted with a note

## Backward Compatibility

- Old reviews with incomplete evidence store: export shows [E1] with "unknown" location and "证据详情不可用" message.
- No evidence records: appendix still renders with display refs and file paths if available.
- Finding objects without display_map: raw ev_* IDs are preserved (passthrough).
- Frontend components: `evidenceDisplayMap` prop defaults to `{}`.

## Limitations

- Backend storage is still temporary (SQLite in /tmp on free Render).
- Snippets depend on evidence availability at review time.
- Persistent DB remains a future optional upgrade.
- Evidence display map is computed per-request from stored findings (not cached).
