## 1. Why This Hotfix Exists

V3.5.10 introduced the LLM mode selector (Mock vs MiMo) but contained a critical execution bug:

- Frontend sent `llm_mode` correctly.
- Backend received `llm_mode` in the request.
- But `runner._run()` used `self.llm_client` (built once at init from `settings.use_mock_llm`).
- In production (`USE_MOCK_LLM=false`), `self.llm_client` was always the MiMo/OpenAI client.
- Therefore selecting "Mock" in the UI still ran real MiMo API calls.

The fix: `runner._run()` now calls `build_llm_client_for_mode(settings, llm_mode)` per task, ensuring the selected mode is honored.

| Check | Result |

| OPENAI_API_KEY missing error | ✅ No — confirms MiMo provider is used |
| MiMo provider routing | ✅ Correct — DNS failure proves it hits MiMo endpoint |

**Root Cause of Failure:** DNS resolution failure for `token-plan-cn.xiaomimimo.com` from Render's US-based infrastructure. The MiMo API endpoint is a China-region Xiaomi service that is not reachable from US cloud servers. This is an **infrastructure limitation**, not a code bug.

**Verdict:** ⚠️ CONDITIONAL PASS — MiMo mode correctly routes to MiMo provider (no OPENAI_API_KEY error). The DNS failure is a platform limitation. MiMo mode works correctly from China-accessible infrastructure.
