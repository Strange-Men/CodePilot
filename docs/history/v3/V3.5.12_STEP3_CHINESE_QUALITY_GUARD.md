# V3.5.12 Step 3 — Chinese Quality Guard for Reports and Findings

> Date: 2026-06-17
> Status: Complete
> Branch: master

## Problem

Chinese (zh) reports generated by CodePilot contained English natural-language
sentences and internal engineering phrases mixed into Chinese sections. This
happened because:

1. MiMo LLM sometimes generates English text in `display.zh` fields.
2. The localization pipeline (`localization.py`) translates known labels and
   prose but cannot catch novel English sentences generated by the LLM.
3. Common English phrases like "Changes require updates in multiple locations"
   or "validated symbols" leaked through untranslated.

## Allowed English in zh Reports

The following English content is explicitly allowed and will NOT be flagged:

| Category | Examples |
|----------|----------|
| File paths | `src/flask/app.py`, `backend/api/reviews.py` |
| Code symbols | `send_static_file`, `OpenAICompatibleClient` |
| Commands | `pytest tests/test_cli.py`, `npm run build` |
| Framework/library names | Flask, FastAPI, React, SQLite |
| Model/provider names | MiMo, OpenAI, Claude, GPT |
| Evidence display refs | [E1], [E2], [E3] |
| Code blocks | ` ```python ... ``` ` |
| Inline code | `` `variable_name` `` |
| Tech abbreviations | api, cli, json, yaml, sql |

## Disallowed English Leakage

The following English content is flagged and normalized:

| Category | Examples |
|----------|----------|
| English sentences | "Changes require updates in multiple locations" |
| English labels | Recommendation, Impact, Caveat, Grounding |
| Severity values | medium → 中, low → 低, high → 高 |
| Status values | completed → 已完成, failed → 失败 |
| Internal phrases | "validated symbols" → "已验证符号" |
| Raw evidence IDs | `ev_abc123...` → [E?] or [E1] |

## Implementation Summary

### New File: `backend/reviewers/zh_quality.py`

Deterministic, rule-based Chinese quality guard. No LLM calls.

**Functions:**

- `is_allowed_english_token(text)` — checks if a token is an allowed English
  category (file path, code symbol, command, tech name, evidence ref).
- `detect_english_natural_language_leak(text)` — detects English natural-language
  fragments using a 4+ common-word heuristic outside code blocks.
- `normalize_zh_text(text)` — normalizes a single text field with phrase and
  label replacements.
- `normalize_zh_markdown(markdown)` — normalizes full markdown report: applies
  phrase/label/severity/status replacements while preserving code blocks, inline
  code, file paths, and evidence refs.
- `redact_or_replace_raw_evidence_ids(markdown, display_map)` — replaces raw
  `ev_*` IDs with display refs or `[E?]` fallback.
- `assert_no_obvious_zh_leak(markdown)` — quality assertion for testing.

## Raw ev_* Regression Rule

- All raw `ev_*` IDs (pattern: `ev_` + 20 hex chars) are replaced in
  user-facing zh and en Markdown.
- Known IDs map to `[E1]`, `[E2]`, etc. via `EvidenceDisplayMap`.
- Unknown IDs become `[E?]` with no raw leakage.
- Internal DB/storage is NOT modified — raw IDs remain for validation.

## Where Guard Is Applied

```
Report Pipeline (zh):
  report_composer.py  →  English canonical report
       ↓
  localized_report_renderer.py
    - translate_report_headings()     → Chinese headings
    - translate_report_labels()       → Chinese bold labels
    - translate_report_prose()        → Known English → Chinese
    - translate_enum_values()         → severity/status/category
    - generate_priority_section()     → 优先处理建议
    - display_map.replace_in_text()   → ev_* → [E1]/[E2]
    - normalize_zh_markdown()         → FINAL quality guard ← NEW
       ↓
  reviews.py (API/export)
    - _render_bilingual_report()      → display.zh fields
    - normalize_zh_markdown()         → SECOND pass ← NEW
    - normalize_zh_text()             → per-field normalization ← NEW
```

## Limitations

1. **Deterministic guard is not full machine translation.** It catches known
   patterns and common English phrases but cannot translate arbitrary novel
   English sentences.

2. **Rare English phrases may need future rule additions.** If MiMo generates
   new English phrases not in the replacement dictionary, they will pass through.
   The `detect_english_natural_language_leak()` function can detect them, but
   automatic replacement requires adding entries to `_PHRASE_REPLACEMENTS`.

3. **Code symbols that happen to be English words** (e.g., a function named
   `changes()`) are preserved as-is. The guard uses a common-word dictionary
   to distinguish natural language from code identifiers.

4. **Inline code is never modified.** If English text appears inside backticks
   as part of a code snippet, it is preserved.

## Tests

**File:** `tests/unit/test_zh_quality_guard.py` — 73 tests covering:

1. Allowed English tokens (file paths, symbols, commands, tech names, refs)
2. English leak detection (sentences, code blocks, inline code, tables)
3. Text normalization (phrase replacements, code preservation)
4. Markdown normalization (code blocks, severity, status, evidence refs)
5. Raw ev_* regression (replacement, display mapping, no leakage)
6. Quality assertion (clean reports, raw IDs, English labels)
7. English report unchanged (no accidental translation)
8. Enum translations (severity/status in parentheses and tables)
9. Phrase replacement completeness (parametrized)
10. No secrets in output
11. Legacy/old reviews (without bilingual display, with raw ev_*)
