### 9. Bottleneck Analysis

#### Where time is spent (Balanced, 418s total)

| Component | Time | % of Total |
|---|---|---|
| LLM requests (agent work) | ~413s | 98.8% |
| Clone | 2.6s | 0.6% |
| Parse | 1.1s | 0.3% |
| Persistence | 0.06s | 0.01% |

**The bottleneck is overwhelmingly MiMo LLM latency.** Each agent takes 160–413s, and the pipeline waits for the slowest agent (RefactorAgent at 413s).

#### Why agents take so long

1. **MiMo model is slow per request** — individual LLM calls range from 76s to 336s
2. **ReadTimeout causes retries** — 2 timeout events, each adding retry overhead
3. **Agents make 1-2 LLM calls each** — some agents retry after timeout, doubling their time
4. **Prompt size** — balanced mode sends larger context to each agent

#### Concurrency effectiveness

All 4 agents run in parallel. The wall-clock equals the slowest agent (413s), not the sum. Concurrency is working correctly.

### 10. Step 3 Architecture Recommendation

#### Decision Rules Applied

| Rule | Condition | Met? |
|---|---|---|
| 1 | ≤ 3 min, no rate-limit | ❌ |
| 2 | 3–6 min | ❌ (6.97 min) |
| 3 | > 6 min | ✅ |
| 4 | > 8 min | ❌ |
| 5 | 429/rate-limit storms | ❌ (only 2 timeouts) |
| 6 | Bilingual adds major latency | ❌ (bilingual is instant) |

**Rule 3 applies:** concurrency=4 balanced is > 6 minutes.

#### Recommendation

**Step 3 should focus on two parallel tracks:**

**Track A: Reduce LLM call count (2-call grouped agents)**
- Current: 4 agents × 1-2 LLM calls = 4-8 calls, bottlenecked by slowest
- Proposed: 2 grouped agents × 1 call each = 2 calls
- Group 1: ArchitectureAgent + CodeSmellAgent (structural + smell analysis)
- Group 2: MaintainabilityAgent + RefactorAgent (maintainability + refactor suggestions)
- Expected impact: ~50% wall-clock reduction (from ~7 min to ~3.5 min)

**Track B: Fix empty-finding quality problem**
- 3 of 4 agents return empty findings in both speed modes
- This is a prompt/output issue with MiMo, not a latency issue
- Investigate: prompt structure, output schema enforcement, MiMo model behavior
- May need: simpler output schema, explicit "find at least 1 issue" instruction, or different prompting strategy for MiMo

**Not recommended:**
- Single-call multi-agent: too complex for MVP, risk of quality degradation
- Chinese-primary output: bilingual is already instant, no latency benefit
- Concurrency reduction: timeouts are minor (2 events), not a storm

#### Priority

1. **First:** Fix empty-finding quality (Track B) — the review is useless if 3/4 agents find nothing
2. **Second:** Implement 2-call grouped agents (Track A) — reduces latency after quality is fixed
