# V3.5.10 MiMo Provider Hotfix

## Production Symptom

All agents failed on Render with:

```
RuntimeError: OPENAI_API_KEY is missing. Set USE_MOCK_LLM=true to run without an API.
```

Despite `startup_config` showing `provider=mimo` and production env containing
`MIMO_API_KEY`, `MIMO_BASE_URL`, `MIMO_MODEL_NAME`.

## Root Cause

`OpenAICompatibleClient.generate_review()` always checked
`self.settings.openai_api_key` regardless of which provider was active.
`build_llm_client()` created the client without mapping MiMo settings to the
OpenAI-compatible fields that the client internally used.

The existing `build_llm_client_for_mode()` correctly mapped MiMo settings, but
it was only used for explicit API-level `llm_mode="mimo"` requests — not for the
default production path.

## Fix

Introduced `ResolvedLLMConfig` and `resolve_llm_config()`:

- `resolve_llm_config(settings)` determines the active provider (MiMo priority
  when `MIMO_API_KEY` is set, OpenAI fallback) and returns a single resolved
  config with the correct `provider`, `model`, `base_url`, `api_key`, and
  `api_key_env_name`.
- `OpenAICompatibleClient` stores `self.resolved` at construction time and uses
  it for all API calls, key checks, and logging.
- `build_llm_client()` calls `resolve_llm_config()` and fails fast with the
  correct env var name if the key is missing.
- Missing-key errors now name the correct provider:
  - MiMo: `MIMO_API_KEY is missing. Set USE_MOCK_LLM=true to run without a real API.`
  - OpenAI: `OPENAI_API_KEY is missing. Set USE_MOCK_LLM=true to run without a real API.`

## Render Env Checklist

For MiMo production:

```
USE_MOCK_LLM=false
ENABLE_REAL_LLM=true
REVIEW_ENGINE=v3_multi_agent
REVIEW_AGENT_MODE=separate
REVIEW_AGENT_CONCURRENCY=4
REVIEW_SPEED_MODE=balanced

MIMO_API_KEY=<your key>
MIMO_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
MIMO_MODEL_NAME=mimo-v2.5-pro

# OPENAI_API_KEY is NOT needed for MiMo
```

## Verification Steps

1. After redeploy, check `startup_config` log shows `provider=mimo model=mimo-v2.5-pro`.
2. Run one review against `https://github.com/pallets/flask`.
3. Check logs for `event=agent_failed` — should see none with `OPENAI_API_KEY` errors.
4. Review should complete with at least some agents succeeding.
