# V3.5.12 Step 1: Export Error Handling and Stale History Fix

## Symptom

When clicking "Export Markdown" (导出 Markdown) for a review that no longer exists on the backend, the browser navigates directly to the API endpoint and displays raw JSON:

```json
{"error":"Review not found","code":"review_not_found","detail":"..."}
```

This occurs on Render's free tier where the SQLite database is stored at `/tmp/codepilot.db` and is cleared on every redeploy/restart.

## Root Cause

### Export Navigation Bug

The export button in `ControlSidebar.tsx` used a direct `<a href>` link:

```tsx
<a href={getReviewExportUrl(review.task_id, { lang: language })}>
```

When the review no longer exists, the browser follows the link and displays the JSON error response directly, creating a confusing user experience.

### Stale History After Redeploy

On Render's free tier:
- Database path: `DATABASE_PATH=/tmp/codepilot.db`
- After redeploy/restart, all review records are lost
- Frontend may still show completed reviews in history (if page wasn't refreshed)
- Export button remains active for these stale reviews

## Fix

### Frontend Export Fix

Changed export from direct link navigation to `fetch()` + Blob download:

1. **New `exportReview()` function** in `lib/api.ts`:
   - Uses `fetch()` to call the export endpoint
   - Returns `{ blob, filename }` on success
   - Throws `CodePilotApiError` on failure
   - Parses filename from `Content-Disposition` header
   - Falls back to `codepilot-review-{id}-{lang}.md`

2. **Updated export button** in `ControlSidebar.tsx`:
   - Replaced `<a href>` with `<button onClick>`
   - Calls `exportReview()` and creates Blob download
   - Shows friendly error messages on failure
   - Calls `onStaleReview()` when review_not_found

3. **Error handling**:
   - `review_not_found`: "Report not found. The backend may have been redeployed..."
   - `review_not_ready`: "This report is not yet available for export..."
   - Network errors: "Export failed. Please check your network..."

### Stale History Handling

Added `handleStaleReview()` in `WorkspaceShell.tsx`:

- Removes stale review from history array
- Clears current review selection if it points to the stale ID
- Resets workspace to initial state
- Applied to:
  - Export errors (review_not_found)
  - Structured data loading errors
  - Language change re-fetch errors

### Backend Export Headers

The backend export endpoint already had proper headers:

```python
return Response(
    content=content,
    media_type="text/markdown; charset=utf-8",
    headers={
        "Content-Disposition": f'attachment; filename="{filename}"',
        "Content-Type": "text/markdown; charset=utf-8",
    },
)
```

No backend changes were required.

## Production Note

On Render's free tier:
- Backend history is temporary (SQLite at `/tmp`)
- Review data is lost on redeploy/restart
- **Exported Markdown is the durable artifact** — users should export important reviews immediately

For persistent history, consider:
- Render paid disk ($7/mo for persistent disk)
- External database (Postgres, Supabase, Neon)
- Client-side IndexedDB (future enhancement)

## Behavior Before Fix

| Scenario | Behavior |
|----------|----------|
| Export completed review | Browser navigates to API, downloads .md |
| Export stale review | Browser shows raw JSON error page |
| Export failed review | Browser shows raw JSON error page |
| Network error during export | Browser shows network error page |

## Behavior After Fix

| Scenario | Behavior |
|----------|----------|
| Export completed review | Blob download, user stays on page |
| Export stale review | Friendly error message, stale review removed from history |
| Export failed review | Friendly error message: "not yet available" |
| Network error during export | Friendly error message: "check network" |
