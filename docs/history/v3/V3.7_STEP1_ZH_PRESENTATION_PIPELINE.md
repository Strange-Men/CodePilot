# V3.7 Step 1 — Rebuild Chinese Presentation Pipeline

> Status: Implemented
> Date: 2026-06-17
> Scope: Backend Chinese report quality — no frontend UI changes

## Problem

V3.6 Chinese reports still contained English natural-language text in Chinese sections:

- **impact**: "Increases maintenance burden and raises the risk of regressions..."
- **recommendation**: "Review if the duplication is intentional for backward compatibility."
- **first_step**: "Extract common logic to reduce duplication and improve maintainability."
- **caveat**: "This boundary is part of a public API; changing it may break downstream consumers."
- **repo summary**: "Python 仓库 with 83 Python files。Supporting modules。Dependency structure。"
- **evidence appendix**: "This evidence was derived from parsed code symbols..."
- **evidence labels**: "Type / Symbol / Description / Related findings" (English)

## Root Cause

The existing `zh_quality.py` was a **post-render** phrase replacement layer. It could fix known English phrases via string replacement, but it could not reliably fix arbitrary English generated by the LLM into `display.zh` fields.

The flow was:
1. LLM generates `display.zh` fields (sometimes with English leakage)
2. `_render_bilingual_report()` replaces English prose with `display.zh` values
3. `normalize_zh_markdown()` tries to catch remaining English via phrase tables
4. Phrase tables can't cover all possible English patterns → leakage persists

## Why Post-Render Replacement Was Insufficient

1. **Unpredictable input**: The LLM generates arbitrary English text for `display.zh` fields. No finite phrase table can match all possible English sentences.

2. **Late detection**: By the time `normalize_zh_markdown()` runs, the English text is already embedded in the rendered markdown. Fixing it requires pattern matching on the final output, which is fragile.

3. **Scattered rules**: Chinese quality rules were spread across `zh_quality.py`, `localized_report_renderer.py`, `report_composer.py`, and `reviews.py`. No single module owned the complete pipeline.

## Solution: Centralized `zh_presentation.py`

### New Module

`backend/reviewers/zh_presentation.py` owns all Chinese quality rules:

```
zh_presentation.py
├── is_english_leakage()          # Detect English in zh fields
├── repair_zh_field()             # Single field repair with templates
├── repair_zh_validation_tests()  # Validation tests list repair
├── repair_zh_display_fields()    # Finding-level repair
├── repair_zh_findings()          # Batch finding repair
├── repair_zh_metadata()          # Post-render metadata cleanup
├── validate_zh_fields()          # Validation for testing
├── prepare_zh_report()           # Pre-render pipeline entry
└── finalize_zh_report()          # Post-render pipeline entry
```

### Architecture

```
                    ┌─────────────────────────────────────┐
                    │         zh_presentation.py          │
                    │                                     │
  display.zh ──────►│  1. is_english_leakage()            │
  fields            │  2. repair_zh_field() with templates│──► repaired findings
                    │  3. repair_zh_validation_tests()    │
                    └─────────────────────────────────────┘
                                       │
                                       ▼
                    ┌─────────────────────────────────────┐
                    │  Render pipeline (localization.py,  │
                    │  localized_report_renderer.py)      │
                    └─────────────────────────────────────┘
                                       │
                                       ▼
                    ┌─────────────────────────────────────┐
                    │         zh_presentation.py          │
                    │                                     │
  rendered ─────────►│  4. repair_zh_metadata()            │
  markdown          │  5. normalize_zh_markdown() fallback│──► final zh report
                    └─────────────────────────────────────┘
```

### Validation/Repair Flow

**Pre-render (before report rendering):**

1. `repair_zh_findings()` iterates all findings
2. For each finding, `repair_zh_display_fields()` checks each `display.zh` field
3. `is_english_leakage()` detects English text:
   - Has Chinese characters? → Keep (already Chinese)
   - Is a file path, code symbol, command, tech name, or evidence ref? → Keep (allowed English)
   - Single common English word? → Repair
   - Multiple English words, no Chinese? → Repair
4. English fields are replaced with category-specific Chinese templates

**Post-render (after report rendering):**

1. `repair_zh_metadata()` fixes metadata patterns:
   - Evidence appendix labels: `Type` → `类型`, `Symbol` → `符号`
   - Repo summary: `Python 仓库 with` → `Python 仓库，包含`
   - Evidence description: `This evidence was derived` → `该证据来自`
2. `normalize_zh_markdown()` (from `zh_quality.py`) handles remaining phrase/label cleanup

### Allowed English (Preserved)

These English tokens are intentionally kept in zh reports:

- **File paths**: `src/flask/app.py`, `backend/api/reviews.py`
- **Code symbols**: `send_static_file`, `OpenAICompatibleClient`, `MAX_ENTRIES`
- **Commands**: `pytest tests/test_cli.py`, `npm run build`
- **Tech names**: Flask, FastAPI, React, SQLite, MiMo, OpenAI, API, URL, JSON, HTTP, CLI, UI, DB, SQL
- **Evidence refs**: `[E1]`, `[E2]`
- **Code blocks**: `` ```python ... ``` ``

### Integration Points

**`reviews.py`** (API handler):
- One call to `repair_zh_findings()` before rendering bilingual report
- One call to `finalize_zh_report()` after rendering

**`localized_report_renderer.py`** (renderer):
- One call to `finalize_zh_report()` instead of `normalize_zh_markdown()`

**`zh_quality.py`** (unchanged):
- Remains as the final fallback for phrase/label cleanup
- `normalize_zh_markdown()` is called by `finalize_zh_report()`

## Limitations

1. **Template-based repair**: The repair uses category-specific templates, not LLM translation. The repaired text is generic but correct. For more specific Chinese text, the LLM translation pipeline (localization_service.py) should generate better `display.zh` fields upstream.

2. **Single-word severity values**: Words like "high", "medium", "low" are not detected by `is_english_leakage()` (they're not in `_COMMON_ENGLISH_WORDS`). These are handled by `normalize_zh_markdown()` which translates severity values.

3. **Mixed Chinese+English fields**: Fields that already contain Chinese characters are not repaired, even if they also contain English sentences. The assumption is that if the LLM generated some Chinese, the field is intentionally bilingual.

4. **No LLM calls**: This module is purely deterministic (regex/string based). It does not call any LLM for translation.
