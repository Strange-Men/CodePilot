## 7. Root Cause Analysis

### Group 1 Timeout

The grouped prompt for ArchitectureAgent + MaintainabilityAgent includes:
- Combined evidence from both agents
- Detailed bilingual display instructions
- Per-agent evidence sections

This produces a prompt that exceeds the MiMo model's ability to respond
within the 180s read timeout. Multiple retries (up to 3 attempts) each
timeout, resulting in ~549s total wall-clock time.

### Group 2 Parse Error

The LLM returned JSON that the parser could not handle. The error
"indices must be integers or slices, not str" indicates the response
structure did not match the expected `{"agent_outputs": {...}}` format.
The same error also affects MaintainabilityAgent in separate mode,
suggesting a pre-existing parsing fragility that grouped mode amplifies.

### Why Separate Mode Is Faster

Separate mode runs 4 agents concurrently (ThreadPoolExecutor with 4
workers). Each agent sends a focused, smaller prompt to the LLM. The
wall-clock time is determined by the slowest single agent (~176s), not
the sum of all agents. Grouped mode sends 2 larger prompts that each
take longer than any single separate prompt.

---

## 8. Recommendation

### KEEP SEPARATE DEFAULT

**Rationale:**

1. **Grouped is 3x slower**, not faster — the opposite of the intended benefit.
2. **Grouped produces 0 findings** — complete quality failure.
3. **Grouped has 100% agent failure rate** — all 4 logical agents failed.
4. **Grouped causes timeouts** — the prompt is too large for MiMo's 180s read timeout.
5. **Grouped amplifies parsing errors** — the same parser fragility affects grouped more severely.
6. **Separate mode works** — 3/4 agents complete, 4 findings produced, 183.8s wall-clock.

### Grouped Mode Status

Grouped mode should remain behind the `REVIEW_AGENT_MODE=grouped` flag
but should NOT be promoted or made default. It requires significant
rework before it can be considered viable:

1. **Reduce grouped prompt size** — evidence compression, fewer instructions, or smaller groups.
2. **Increase read timeout for grouped calls** — or implement streaming.
3. **Fix parser fragility** — the "list indices" error affects both modes.
4. **Add fallback to separate mode** — if grouped fails, retry as separate.

---

## 9. Risks and Limitations

1. **Single run:** Each mode was benchmarked once. Variance is not measured.
2. **Self-review:** CodePilot reviewed itself, which may not represent typical usage.
3. **Network issue:** GitHub was unreachable; local clone was used. Clone time is negligible and equal for both modes.
4. **MiMo model:** Results are specific to mimo-v2.5-pro. Other models may behave differently.
5. **Pre-existing parser bug:** The "list indices" error also affects separate mode (MaintainabilityAgent). This is not a grouped-mode regression but a shared weakness.
6. **No Chinese report API test:** Chinese readiness was checked via DB content, not via live API endpoint. **Step 4 confirmed this was a false positive** — the zh rendering pipeline works correctly (verified by `test_zh_report_quality.py`).
