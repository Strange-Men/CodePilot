## 1. What Was Implemented

A 2-call grouped agent review mode that reduces physical LLM calls from 4 to 2 while preserving 4 logical agent identities. The feature is behind an opt-in feature flag.

## 2. Feature Flag Usage

```
REVIEW_AGENT_MODE=separate|grouped
```

| Value | Behavior |
|-------|----------|
| `separate` (default) | V3.5.9 behavior: 4 independent agents, 4 LLM calls. Unchanged. |
| `grouped` | V3.5.10 grouped mode: 2 grouped calls, 4 logical agent outputs. |

Invalid values fall back to `separate` with a logged warning.

### Usage Examples

```bash
# Default (separate mode — unchanged V3.5.9 behavior)
python scripts/benchmark_real_review.py --repo-url https://github.com/owner/repo

# Grouped mode
python scripts/benchmark_real_review.py --repo-url https://github.com/owner/repo --agent-mode grouped

# Grouped with concurrency override
python scripts/benchmark_real_review.py --repo-url https://github.com/owner/repo --agent-mode grouped --concurrency 4
```

## 5. Failure/Salvage Behavior

### Group Independence
- If Group 1 fails, Group 2 still runs.
- If Group 2 fails, Group 1's results are still valid.

### Partial Salvage
If a grouped response contains one valid logical agent output and one invalid:
- The valid output is parsed and validated normally.
- The invalid output is recorded as failed with appropriate error.
- The valid agent's findings are preserved (salvaged).

### Error Isolation
- Each logical agent's `AgentExecutionState` is built independently.
- One logical agent's failure does not affect the other's state.
- `no_findings_reason` is recorded per logical agent.
- Error messages are per logical agent.

### Fallback
- Invalid `agent_mode` values fall back to `separate` with a logged warning.
- No automatic fallback from grouped to separate on LLM failure (grouped failures are isolated per-agent).

## 8. Known Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| Larger prompt reduces LLM reliability | Medium | High | Benchmark quality; per-agent validation catches issues |
| One grouped call failure affects 2 agents | Low | Medium | Salvage valid output; per-agent error isolation |
| Schema complexity increases parse failures | Medium | Medium | Robust parser with code-fence stripping; retry once |
| Quality drops for individual findings | Low | Medium | Validate per-agent; compare finding counts in benchmark |

## 9. Next Step

Run real benchmark comparing `separate` vs `grouped` on same repo/model:
1. If grouped is ≥30% faster with comparable quality → consider making grouped default
2. If grouped is <30% faster or quality drops → keep separate as default
3. If grouped fails frequently → investigate prompt/schema before proceeding
